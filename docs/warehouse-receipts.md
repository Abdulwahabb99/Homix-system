# الاستلامات

تبويب «الاستلامات» داخل الشحن والتوصيل، بنفس تصميم هوميكس الحالي.

- اختيار عدة عمليات وتسجيل استلامها من المصنع، مع التاريخ واسم المندوب والملاحظات.
- بيانات الاستلام محفوظة على الطلب؛ يعتمد التنفيذ على تقسيم الطلبات إلى بند لكل عملية.
- التسجيل يحدّث حالة الطلب والشحنة إلى «في المخزن» وتاريخ الاستلام تلقائيًا، ويضبط التوصيل بواسطة هوميكس.
- يمنع تكرار الاستلام ويستبعد العمليات غير المتاحة، ولا يضيف البضاعة إلى مخزون البيع الحر.
- إصدار السند خطوة منفصلة عن الاستلام، ويمكن جمع عدة عمليات مستلمة في سند واحد وطباعته بحجم A4.
- إصدار سند جديد لنفس العمليات يستبدل رقم السند المسجل عليها؛ السجل يعرض التجميعات الحالية وليس أرشيفًا ثابتًا للسندات السابقة. بيانات الأصناف تُقرأ من السجلات الحالية.
- مسؤول الاستلام هو المستخدم المسجل. العرض يتطلب `ship_inventory_view`، والتسجيل وإصدار سند جديد يتطلبان أيضًا `ship_edit`.

## تجهيز قاعدة البيانات

من مستودع `homix` بعد ضبط بيئة قاعدة البيانات المقصودة:

```sh
npm run db:setup-warehouse-receipts
npm run build
```

الأمر يشغّل `migrations/add-warehouse-receiving-columns.js` لإضافة حقول الاستلام إلى `orders` وفهرس رقم السند وتسلسل أرقامه. يمكن إعادة تشغيله. يجب تنفيذه قبل نشر التعديلات؛ لم يُشغّل على الإنتاج ضمن هذا العمل.

## API

- `GET /shipments/receipts` — المستلم، مع `page`, `search`, `date`.
- `GET /shipments/receipts/candidates` — المتاح للاستلام.
- `POST /shipments/receipts` — `{ orderIds, receivedDate: "YYYY-MM-DD", senderName, notes }`.
- `POST /shipments/receipts/documents` — `{ orderIds }` لإصدار سند.
- `GET /shipments/receipts/documents` — التجميعات الحالية.
- `GET /shipments/receipts/documents/:number` — عرض سند برقمه.

الحفظ داخل transaction مع قفل الطلبات لمنع الاستلام المتكرر. تواريخ العمل بتوقيت القاهرة.
